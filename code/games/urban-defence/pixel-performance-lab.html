Three-building pixel workload

Blueprint squares match the visible building squares inside each empty planned cell. At scales of four display pixels or larger, building and delivery squares leave one-pixel right/bottom visual gutters for roomier repair openings; two-pixel cells stay full-sized. Occupancy and support remain full-cell physics. Occupied cells show no blueprint border.

Settled pixels contribute weight along connected paths to terrain. Support capacity is 128 cell-weight units; overload turns support cells into debris. Reported load and overload failures are per world. This is static load sharing, not bending or rigid-body dynamics.

Three tall frames run together on one browser animation loop, each in its own 160 by 90 particle world. All three basins are breached; the middle foundation is blasted. Each frame starts after 40 simulated seconds of dry construction so crawling material is already active. Preparation is excluded from startup FPS measurement.

This is an aggregate simulation and rendering workload, not three buildings sharing terrain or water. It does not measure cross-building collisions, a full battlefield, workers or live-game integration. All three canvases redraw each animation frame, even when below the viewport. Hidden tabs are reported separately.
